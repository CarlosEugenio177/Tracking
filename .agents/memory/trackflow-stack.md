**TrackFlow** is "the GitHub of Digital Tracking" — a multi-tenant SaaS for digital marketing governance. Initial market: Brazil.

## Artifacts
- `artifacts/trackflow` — React + Vite frontend, preview path `/`
- `artifacts/api-server` — Express API server, port 8080, prefix `/api`

## Libraries
- `lib/db` — Drizzle ORM + PostgreSQL. Schema: workspaces, workspace_members, campaigns, links, webhook_endpoints, webhook_events, tracking_events, conversions
- `lib/api-zod` — Zod schemas generated from OpenAPI spec (lib/api-spec/openapi.yaml) via Orval
- `lib/api-client-react` — React Query hooks generated by Orval (useListWorkspaces, useGetDashboardStats, etc.)

## Auth
- Replit-managed Clerk. Keys: CLERK_PUBLISHABLE_KEY, CLERK_SECRET_KEY, VITE_CLERK_PUBLISHABLE_KEY
- Frontend uses `publishableKeyFromHost` from `@clerk/react/internal`
- Backend uses `clerkMiddleware` + `requireAuth` middleware extracting userId
- All workspace-scoped routes also use `requireWorkspaceAccess` (see trackflow-workspace-auth.md)

## Seed data
- Demo workspace: slug `agencia-demo`, id 2, owner_clerk_id `demo-owner-id`
- 4 campaigns, 4 links, 2 webhook endpoints, 3 webhook events, 7 tracking events, 5 conversions

## OpenAPI → Orval
- Spec: `lib/api-spec/openapi.yaml`
- Orval generates hooks in `lib/api-client-react/src/generated/`
- `lib/api-zod/src/index.ts` exports only from `./generated/api` (not `./generated/types`) to avoid name collision
